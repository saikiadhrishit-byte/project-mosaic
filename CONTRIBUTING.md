# Contributing

Thank you for your interest in Project Nysor.

This repository is an early-stage experimental architecture and research project. The goal is to communicate the engine vision clearly enough that developers, compiler designers, engine architects, and contributors can evaluate and improve the design.

## Contribution Areas

Useful contributions may include:

- clarifying the architecture and terminology;
- improving the Block Standard draft;
- identifying research topics and references;
- improving the project roadmap;
- reviewing technical assumptions and trade-offs;
- suggesting a prototype plan;
- proposing package and extension design patterns.

## Expectations

The repository should be a place for constructive technical criticism. Contributors should be careful to distinguish clearly between:

- research directions;
- draft architecture decisions;
- unresolved open questions;
- implementation claims.

## Process

1. Open or join a discussion around an architectural question.
2. Describe assumptions honestly.
3. Reference existing technologies only as research analogies, not as proof that the design is the same.
4. Prefer precise technical language and clear trade-off explanations.
5. Avoid claiming that prototype ideas are complete or final.

## Documentation First

This repository is documentation-first. In general, changes should strengthen the architecture narrative, clarify the Block Standard, improve the research and roadmap sections, or add new technical discussion where the project has an unresolved question.

## Code of Conduct

Please read and follow the project's [Code of Conduct](CODE_OF_CONDUCT.md).
